rtextures — Images, Textures & Render Targets

src/rtextures.c handles CPU-side image data (Image), GPU textures (Texture2D), cubemaps, render textures (FBOs), and the DrawTexture* family.

Data Types
TypeWhere it livesLifecycle
ImageCPU RAM (image.data)LoadImage → manipulate pixels → UnloadImage
Texture2DGPU (texture.id = OpenGL texture name)LoadTextureFromImage → draw → UnloadTexture
RenderTexture2DGPU FBO + color textureLoadRenderTexture → BeginTextureMode → UnloadRenderTexture

The typical load path decodes a file to CPU memory first, then uploads once to the GPU:

Texture2D LoadTexture(const char *fileName)
{
    Image image = LoadImage(fileName);       // stb_image / custom decoders
    Texture2D texture = LoadTextureFromImage(image);
    UnloadImage(image);                      // free CPU copy
    return texture;
}
LoadTexture / LoadTextureFromImage
CPU → GPU Upload 
Texture2D LoadTextureFromImage(Image image)
{
    texture.id = rlLoadTexture(
        image.data, image.width, image.height,
        image.format, image.mipmaps);
    texture.width = image.width;
    texture.height = image.height;
    return texture;
}

rlLoadTexture (inside rlgl) calls glGenTextures, glTexImage2D, sets filtering/wrap, and optionally generates mipmaps. Compressed formats (DXT, ETC, ASTC) pass through when supported.

LoadTextureFromImage

Image loading uses bundled stb_image and related decoders in src/external/.

Drawing Textures (2D Quad Path)
DrawTexture(texture, x, y, tint) → DrawTextureEx → DrawTexturePro │ ├─ compute destination quad (position, scale, rotation, origin) ├─ map source Rectangle → UV coordinates │ ├─ rlSetTexture(texture.id) ├─ rlBegin(RL_QUADS) │ per vertex: rlColor4ub(tint) rlTexCoord2f(u,v) rlVertex2f(x,y) └─ rlEnd()

DrawTexturePro is the general form used internally by text rendering and sprite sheets. It handles negative width/height flips and arbitrary sub-rectangles.

Render Textures (Off-Screen)

LoadRenderTexture creates an FBO with a color texture attachment (and depth renderbuffer for 3D content). Drawing flow:

RenderTexture2D target = LoadRenderTexture(800, 600);

BeginTextureMode(target);    // rcore: bind FBO, set ortho viewport
    ClearBackground(BLANK);
    DrawCircle(400, 300, 100, RED);   // renders into target.texture
EndTextureMode();            // rcore: restore default framebuffer

DrawTexture(target.texture, 0, 0, WHITE);  // blit to screen
LoadRenderTexture BeginTextureMode / EndTextureMode

Note: OpenGL FBO origin is bottom-left; raylib's LoadRenderTexture flips the Y texture coordinate when drawing so it appears upright on screen.

Image Processing (CPU)

Before or instead of GPU upload, rtextures provides CPU pixel operations:

  • ImageResize, ImageCrop, ImageFormat — format conversion
  • ImageDrawPixel, ImageDrawRectangle — CPU compositing
  • GenImageColor, GenImageGradient* — procedural images
  • ExportImage — write PNG via stb_image_write

These operate on raw image.data bytes and never touch rlgl until you call LoadTextureFromImage.

Connections
  • rtext builds font atlases as Texture2D and draws glyphs via DrawTexturePro
  • rmodels binds textures as material maps in 3D shaders (separate from 2D batch)
  • rlgl owns rlLoadTexture, FBO helpers, and batch flushing on texture bind
  • rcore manages FBO viewport switching during BeginTextureMode
