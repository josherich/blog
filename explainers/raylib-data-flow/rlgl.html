rlgl — OpenGL Abstraction & Render Batching

src/rlgl.h is a header-only OpenGL wrapper included from rcore.c with #define RLGL_IMPLEMENTATION. It targets OpenGL 1.1 (fixed function), 3.3+ core, and ES 2.0 from a single API.

Why rlgl Exists

raylib modules never call OpenGL directly (except inside rlgl). This gives:

  • One codebase for desktop GL 3.3, legacy GL 1.1, OpenGL ES 2.0, and a software renderer
  • Immediate-mode style API (rlBegin/rlVertex2f/rlEnd) that feeds a modern VBO batch on GL 3.3
  • Centralized shader management, texture binding, and matrix stacks

rlgl can also be extracted as a standalone module — see the rlgl header docs.

rlgl.h introduction
Initialization (rlglInit)

Called from InitWindow after the platform creates an OpenGL context:

void rlglInit(int width, int height)
{
    // 1×1 white default texture (used when no texture bound)
    RLGL.State.defaultTextureId = rlLoadTexture(pixels, 1, 1, ...);

    // Built-in 2D shader (GL 3.3 / ES2)
    rlLoadShaderDefault();

    // CPU-side vertex batch + GPU VBOs/VAO
    RLGL.defaultBatch = rlLoadRenderBatch(
        RL_DEFAULT_BATCH_BUFFERS,
        RL_DEFAULT_BATCH_BUFFER_ELEMENTS);
    RLGL.currentBatch = &RLGL.defaultBatch;

    // Matrix stacks (emulating GL 1.1 push/pop)
    RLGL.State.projection = rlMatrixIdentity();
    RLGL.State.modelview = rlMatrixIdentity();

    // GL state defaults
    glEnable(GL_BLEND);
    glDisable(GL_DEPTH_TEST);   // 2D mode default
    glEnable(GL_CULL_FACE);
}

Render Batch — Core Data Flow

All 2D draw calls (shapes, textures, text) funnel through the same batch. Instead of one GPU draw call per rectangle, vertices accumulate in CPU arrays and flush together.

DrawRectangle / DrawTexturePro / DrawTextCodepoint │ ▼ rlSetTexture(id) ← texture change may flush batch rlBegin(RL_QUADS) rlColor4ub / rlTexCoord2f / rlVertex2f ← append to CPU arrays rlEnd() │ ▼ (deferred until flush) rlDrawRenderBatch(batch) 1. glBufferSubData → upload vertices, texcoords, colors, normals 2. glUseProgram(defaultShader) 3. glUniformMatrix4fv(MVP) 4. For each draw group: bind texture → glDrawArrays

Vertex accumulation (rlVertex3f)

Each rlVertex* call writes position, current texcoord, normal, and color into the active buffer slot, then increments RLGL.State.vertexCounter:

RLGL.currentBatch->vertexBuffer[...].vertices[3*counter] = tx;
RLGL.currentBatch->vertexBuffer[...].texcoords[2*counter] = texcoordx;
RLGL.currentBatch->vertexBuffer[...].colors[4*counter] = colorr;
RLGL.State.vertexCounter++;

Batch flush (rlDrawRenderBatch)

Uploads all pending vertices and iterates draw groups (each group shares texture, primitive mode, and shader):

void rlDrawRenderBatch(rlRenderBatch *batch)
{
    glBufferSubData(..., batch->vertices);
    glBufferSubData(..., batch->texcoords);
    glBufferSubData(..., batch->colors);

    glUseProgram(RLGL.State.currentShaderId);
    Matrix matMVP = rlMatrixMultiply(modelview, projection);
    glUniformMatrix4fv(..., matMVP);

    // per draw-call: bind texture, glDrawArrays(mode, offset, count)
}
rlDrawRenderBatch

rlDrawRenderBatchActive() is called at EndDrawing, mode switches, and texture changes — anything that would break batch coherency.

When the Batch Flushes Early

The batch splits (issues an intermediate draw) when:

  • Vertex buffer capacity is reached
  • Texture ID changes (rlSetTexture with a different bound texture)
  • Shader changes (3D DrawMesh uses custom shaders)
  • Draw call count exceeds RL_DEFAULT_BATCH_DRAWCALLS
  • BeginMode3D, BeginTextureMode, or EndDrawing explicitly flush
rlSetTexture flush logic

Understanding flush points explains draw-order bugs: mixing 3D mesh draws with unflushed 2D batch data requires explicit mode boundaries from rcore.

Matrix Stack

rlgl emulates OpenGL 1.1 matrix stacks for 2D transforms. rlPushMatrix/rlPopMatrix operate on the active matrix (modelview by default). DrawTextPro uses this for rotation around an origin.

On GL 3.3, matrices are stored in software (RLGL.State.modelview, RLGL.State.projection) and uploaded as uniforms — there is no fixed-function pipeline.
