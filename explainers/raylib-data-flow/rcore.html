rcore — Window, Input & Frame Loop

src/rcore.c plus platform files under src/platforms/. Owns the global CORE state, orchestrates initialization, the per-frame loop, 2D/3D mode switches, and render-target binding.

Responsibilities
  • Window lifecycle: InitWindow, CloseWindow, fullscreen, HiDPI scaling
  • Input state: keyboard, mouse, gamepad, touch (via platform callbacks)
  • Timing: frame counter, target FPS, GetFrameTime()
  • Drawing orchestration: BeginDrawing, EndDrawing, ClearBackground
  • 3D context: BeginMode3D / EndMode3D projection + depth setup
  • Off-screen rendering: BeginTextureMode / EndTextureMode (FBO)
  • Includes and initializes rlgl, raymath, optional rcamera/rgestures

Initialization Sequence

InitWindow is the single entry point that wires every graphics subsystem together:

void InitWindow(int width, int height, const char *title)
{
    // 1. Store screen size, reset CORE.Input
    CORE.Window.screen.width = width;
    CORE.Window.screen.height = height;

    // 2. Platform: create OS window + OpenGL context
    int result = InitPlatform();   // → rcore_desktop_glfw.c on desktop

    // 3. GPU layer: shaders, default texture, render batch
    rlglInit(CORE.Window.render.width, CORE.Window.render.height);
    SetupViewport(CORE.Window.render.width, CORE.Window.render.height);

    // 4. Default font + shapes texture sharing (enables 2D batching)
    LoadFontDefault();
    SetShapesTexture(GetFontDefault().texture, ...);
}

Platform layer (InitPlatform)

On desktop GLFW builds, InitPlatform initializes GLFW, creates the window with requested flags (resizable, MSAA, transparent, etc.), and creates the OpenGL context. Different platform files swap this backend:

  • rcore_desktop_glfw.c Windows, Linux, macOS
  • rcore_desktop_sdl.c SDL backend
  • rcore_web.c Emscripten / HTML5
  • rcore_android.c Android NDK
  • rcore_drm.c Raspberry Pi KMS/DRM

Per-Frame Loop 
void BeginDrawing(void)
{
    CORE.Time.current = GetTime();
    CORE.Time.update = CORE.Time.current - CORE.Time.previous;
    CORE.Time.previous = CORE.Time.current;

    rlLoadIdentity();
    rlMultMatrixf(MatrixToFloat(CORE.Window.screenScale));
}

void EndDrawing(void)
{
    rlDrawRenderBatchActive();     // flush accumulated 2D vertices

    SwapScreenBuffer();            // glfwSwapBuffers / platform equivalent

    // Frame limiter: sleep until target frame time reached
    if (CORE.Time.frame < CORE.Time.target)
        WaitTime(CORE.Time.target - CORE.Time.frame);

    PollInputEvents();             // keyboard/mouse/gamepad update
    CORE.Time.frameCounter++;
}
BeginDrawing / EndDrawing

The split between update and draw timing lets you measure logic vs rendering separately. SetTargetFPS sets CORE.Time.target for the sleep in EndDrawing.

3D Mode Switching

2D drawing uses an orthographic projection set up in SetupViewport. Entering 3D mode must flush any pending 2D batch first, then replace the projection matrix:

void BeginMode3D(Camera camera)
{
    rlDrawRenderBatchActive();          // flush 2D batch before 3D

    rlMatrixMode(RL_PROJECTION);
    rlPushMatrix();                     // save 2D projection
    rlLoadIdentity();

    if (camera.projection == CAMERA_PERSPECTIVE)
        rlFrustum(-right, right, -top, top, near, far);
    else
        rlOrtho(-right, right, -top, top, near, far);

    rlMatrixMode(RL_MODELVIEW);
    rlLoadIdentity();
    rlMultMatrixf(MatrixToFloat(MatrixLookAt(...)));
    rlEnableDepthTest();
}

EndMode3D flushes again, pops the saved projection, disables depth test, and restores 2D screen scaling.

Render Targets (FBO)

BeginTextureMode redirects drawing to an off-screen framebuffer created by LoadRenderTexture in rtextures. It flushes the current batch, binds the FBO, sets an orthographic projection to the texture size, and tracks CORE.Window.usingFbo.

void BeginTextureMode(RenderTexture2D target)
{
    rlDrawRenderBatchActive();
    rlEnableFramebuffer(target.id);
    rlViewport(0, 0, target.texture.width, target.texture.height);
    rlOrtho(0, target.texture.width, target.texture.height, 0, 0.0f, 1.0f);
    CORE.Window.usingFbo = true;
}
BeginTextureMode / EndTextureMode

Typical use: render a scene to a texture, then draw that texture as a sprite in 2D. Details in rtextures.

How rcore Connects to Other Modules
InitWindow ├── InitPlatform() platform/*.c → OS window, GL context, input callbacks ├── rlglInit() rlgl.h → GPU init (see rlgl.html) ├── LoadFontDefault() rtext.c → default glyph atlas └── SetShapesTexture() rshapes.c → shared 1×1 white region for batching BeginDrawing / EndDrawing └── rlDrawRenderBatchActive() rlgl.h → flush 2D vertices BeginMode3D └── DrawModel() rmodels.c → 3D mesh draws (separate from batch) InitAudioDevice() raudio.c → independent of graphics init

Audio is intentionally separate: call InitAudioDevice() yourself. It does not happen inside InitWindow.
