rshapes — 2D Primitives

src/rshapes.c implements immediate-mode 2D drawing: pixels, lines, circles, rectangles, polygons, splines. Every function computes vertex positions in CPU and submits them through rlgl's batch.

Drawing Pipeline
DrawRectangle(x, y, w, h, color) → DrawRectangleV → DrawRectanglePro │ ├─ compute 4 corner vertices (rotation optional) │ ├─ rlSetTexture(shapesTexture.id) ← white pixel from default font atlas ├─ rlBegin(RL_QUADS) │ rlColor4ub(...) │ rlTexCoord2f(...) rlVertex2f(...) × 4 └─ rlEnd() │ ▼ (batched until flush — see rlgl.html)

Why Shapes Use a Texture

Even solid-color rectangles go through the textured quad path. At init, rcore calls SetShapesTexture with a 1×1 white region from the default font atlas. This lets shapes, text, and textures share the same shader and batch — only the source texture atlas differs.

// InitWindow (rcore.c) wires font white pixel into shapes:
SetShapesTexture(GetFontDefault().texture, (Rectangle){ rec.x+1, rec.y+1, ... });
SetShapesTexture at init

When rtext is disabled, rshapes falls back to rlgl's 1×1 default texture instead.

Example: Filled Rectangle 
void DrawRectanglePro(Rectangle rec, Vector2 origin, float rotation, Color color)
{
    // 1. Compute 4 corners (with optional rotation matrix)
    Vector2 topLeft, topRight, bottomLeft, bottomRight;

    // 2. Submit as textured quad
    rlSetTexture(GetShapesTexture().id);
    rlBegin(RL_QUADS);
        rlColor4ub(color.r, color.g, color.b, color.a);
        rlTexCoord2f(...); rlVertex2f(topLeft.x, topLeft.y);
        rlTexCoord2f(...); rlVertex2f(bottomLeft.x, bottomLeft.y);
        rlTexCoord2f(...); rlVertex2f(bottomRight.x, bottomRight.y);
        rlTexCoord2f(...); rlVertex2f(topRight.x, topRight.y);
    rlEnd();
    rlSetTexture(0);
}

Gradient rectangles set per-vertex colors with different rlColor4ub calls before each vertex — the default shader interpolates color across the quad.

Collision Helpers

rshapes also provides pure-CPU geometry helpers used by game logic (not GPU): CheckCollisionRecs, CheckCollisionCircles, CheckCollisionPointRec, etc. These read rectangle/circle parameters directly — no rlgl involvement.

Connections
  • Upstream: rcore sets shapes texture at init; rlgl batches vertices
  • Parallel: rtextures draws images the same way (textured quads) — shapes just use a solid white texel
  • Shared path with text: rtext ultimately calls DrawTexturePro for each glyph
