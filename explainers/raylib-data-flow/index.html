raylib Architecture Overview

How a C game loop flows from your Draw* calls through batched 2D rendering, shader-based 3D, and miniaudio playback — traced through the actual source modules.

Source snapshot: raysan5/raylib @ 22509ab

What raylib Is

raylib is a plain-C library for games and graphical apps. It wraps platform windowing (GLFW/SDL/RGFW), an OpenGL abstraction layer (rlgl), and optional modules for shapes, textures, text, 3D models, and audio — all behind a single header, raylib.h.

The canonical loop from the README:

#include "raylib.h"

int main(void)
{
    InitWindow(800, 450, "raylib example - basic window");

    while (!WindowShouldClose())
    {
        BeginDrawing();
            ClearBackground(RAYWHITE);
            DrawText("Congrats! You created your first window!", 190, 200, 20, LIGHTGRAY);
        EndDrawing();
    }

    CloseWindow();
    return 0;
}

Every frame, user code sits between BeginDrawing() and EndDrawing(). Inside that window, draw calls accumulate GPU vertex data; at EndDrawing() the batch flushes, the back buffer swaps, and input is polled.

Module Map

raylib compiles as one library but splits responsibilities across source files. rcore.c and rlgl.h are mandatory; other modules are toggled via config.h.

rcore

src/rcore.c + src/platforms/*

Window, input, timing, frame loop, 2D/3D mode switching, render targets.

rlgl

src/rlgl.h

OpenGL 1.1 / 3.3 / ES2 abstraction, render batching, shaders, GPU state.

rshapes

src/rshapes.c

2D primitives — lines, circles, rectangles — via immediate-mode vertices.

rtextures

src/rtextures.c

Image loading, GPU textures, render textures (FBOs), texture drawing.

rtext

src/rtext.c

Font loading (TTF, etc.), glyph atlas, text rendering as textured quads.

rmodels

src/rmodels.c

Mesh loading (glTF, OBJ, IQM), materials, shaders, 3D draw calls.

raudio

src/raudio.c

miniaudio backend, streaming, mixing on a separate thread.

Header-only helpers included from rcore.c: raymath.h (vectors/matrices), rcamera.h (camera controllers), rgestures.h (touch gestures).

Frame Loop Step by Step
1
InitWindow bootstraps everything
Sets screen dimensions, calls InitPlatform() for OS window + GL context, then rlglInit() for GPU resources. Optionally loads the default font and wires it into the shapes module for texture batching.
2
BeginDrawing starts a frame
Records elapsed time, resets the modelview matrix, and applies HiDPI screen scaling. No GPU flush yet — draw calls accumulate in CPU-side batch buffers.
3
Draw calls enqueue vertices
rshapes and rtextures/rtext use rlBegin/rlEnd to append position, texcoord, color, and normal arrays. rmodels bypasses the batch and issues per-mesh shader draws when in 3D mode.
4
rlDrawRenderBatchActive flushes 2D
Uploads batched vertex data with glBufferSubData, sets MVP uniforms, and issues draw calls grouped by texture/shader/mode. Also called when switching 2D↔3D or render targets.
5
EndDrawing presents the frame
Final batch flush, buffer swap (glfwSwapBuffers), frame-time limiter, and input polling. Audio runs independently on miniaudio's callback thread.
