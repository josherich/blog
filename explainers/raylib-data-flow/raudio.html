raudio — Audio Loading & Playback

src/raudio.c wraps miniaudio for device output. Audio runs on a separate callback thread from the graphics loop — no coupling with rlgl or the frame batch.

Architecture Overview
InitAudioDevice() → ma_context_init + ma_device_init (playback) → ma_device_start (device runs continuously) → callback: OnSendAudioDataToDevice() on audio thread LoadSound("hit.wav") → decode to Wave (CPU PCM) → Sound (AudioBuffer wrapper) PlaySound(sound) → AudioBuffer.playing = true (mutex-protected) Each audio callback: for each playing AudioBuffer in linked list: read PCM frames → apply volume/pan/pitch → mix into output buffer

Device Initialization 
void InitAudioDevice(void)
{
    ma_context_init(..., &AUDIO.System.context);
    ma_device_config config = ma_device_config_init(ma_device_type_playback);
    config.playback.format = AUDIO_DEVICE_FORMAT;   // float32
    config.playback.channels = AUDIO_DEVICE_CHANNELS;
    config.sampleRate = AUDIO_DEVICE_SAMPLE_RATE;
    config.dataCallback = OnSendAudioDataToDevice;
    config.noFixedSizedCallback = true;

    ma_device_init(&AUDIO.System.context, &config, &AUDIO.System.device);
    ma_mutex_init(&AUDIO.System.lock);
    ma_device_start(&AUDIO.System.device);
}

The device stays running for the app lifetime. Mixing uses float32 internally for headroom before conversion to the hardware format.

Playback Control 
void PlaySound(Sound sound)
{
    PlayAudioBuffer(sound.stream.buffer);
}

void PlayAudioBuffer(AudioBuffer *buffer)
{
    ma_mutex_lock(&AUDIO.System.lock);
    buffer->playing = true;
    buffer->paused = false;
    buffer->frameCursorPos = 0;
    ma_mutex_unlock(&AUDIO.System.lock);
}
PlayAudioBuffer PlaySound

Volume, pitch, and pan mutate AudioBuffer fields under the same mutex. Pitch adjusts the sample-rate converter (ma_data_converter).

Mixing Callback (Real-Time Path)

The audio device invokes this periodically to fill the output buffer:

static void OnSendAudioDataToDevice(ma_device *pDevice,
                                    void *pFramesOut, ...,
                                    ma_uint32 frameCount)
{
    memset(pFramesOut, 0, ...);   // accumulation buffer

    ma_mutex_lock(&AUDIO.System.lock);
    for (AudioBuffer *buf = AUDIO.Buffer.first; buf; buf = buf->next)
    {
        if (!buf->playing || buf->paused) continue;

        ReadAudioBufferFramesInMixingFormat(buf, tempBuffer, framesToRead);
        // optional processor chain (effects)
        MixAudioFrames(output, tempBuffer, framesRead, buf);
    }
    ma_mutex_unlock(&AUDIO.System.lock);
}
OnSendAudioDataToDevice

All active sounds mix additively into pFramesOut. When a non-looping buffer reaches its end, StopAudioBufferInLockedState clears playing.

Threading Model

Graphics run on the main thread; audio mixes on miniaudio's device thread. A mutex (AUDIO.System.lock) synchronizes buffer list mutations (play/stop) with the callback. Keep main-thread audio calls lightweight — don't decode large files during gameplay; preload or stream instead.

This is independent of BeginDrawing/EndDrawing. Typical game code calls UpdateMusicStream each frame to refill streaming buffers while the callback consumes them.

Decoders

raudio bundles decoders in src/external/:

  • WAV — built-in
  • OGG — stb_vorbis / dr_flac paths
  • MP3, FLAC, XM/MOD — various embedded libraries
  • QOA — quick lossless audio format

All decode to normalized PCM (Wave) before becoming a Sound or streaming queue.

Typical Game Integration 
InitWindow(800, 450, "game");
InitAudioDevice();

Sound jump = LoadSound("jump.wav");
Music bgm = LoadMusicStream("theme.ogg");
PlayMusicStream(bgm);

while (!WindowShouldClose())
{
    UpdateMusicStream(bgm);     // refill stream buffers each frame

    if (IsKeyPressed(KEY_SPACE)) PlaySound(jump);

    BeginDrawing();
        ClearBackground(RAYWHITE);
        // ... draw ...
    EndDrawing();
}

UnloadMusicStream(bgm);
UnloadSound(jump);
CloseAudioDevice();
CloseWindow();
